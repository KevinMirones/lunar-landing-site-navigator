# Specs S01 a S05 implementadas

## Qué se hizo

| Spec | Estado | Lo que aporta |
| --- | --- | --- |
| [S01](../specs/S01-escenarios.md) | hecha | Comparar el mismo sitio en fechas, duraciones o mástiles distintos |
| [S02](../specs/S02-enlaces-compartibles.md) | hecha | Un enlace que abre la misma comparación en otro navegador |
| [S03](../specs/S03-ci-y-despliegue.md) | en curso | Integración continua, límite de peticiones y cabeceras de seguridad; falta desplegar |
| [S04](../specs/S04-buscador-de-puntos.md) | hecha | Mapa de calor alrededor de un punto y los cinco mejores lugares cercanos |
| [S05](../specs/S05-mejores-fechas.md) | hecha | Las cinco mejores fechas de alunizaje del año |

Cada spec está en su propia rama, una sobre otra: `feat/s01-escenarios`, `feat/s02-enlaces-compartibles`, `feat/s03-ci-despliegue`, `feat/s04-buscador-de-puntos` y `feat/s05-mejores-fechas`. La última contiene las cinco.

## Cómo se trabajó

- La lógica se escribió con la prueba primero: cada prueba se vio fallar antes de escribir el código.
- Cada spec se comprobó además en un navegador real, contra el servidor de desarrollo y contra la versión compilada.

## Qué se midió

| Medida | Resultado |
| --- | --- |
| Pruebas automáticas | 104, todas pasan (eran 16) |
| Recalcular seis escenarios de 90 días | menos de 300 ms |
| Buscador de puntos, malla gruesa | 0.6 s |
| Buscador de puntos, malla fina (unas 1260 celdas) | 3.9 s |
| Puntuar un año de fechas de alunizaje | menos de 100 ms |
| Reproducción con el mapa de calor abierto | 144 fotogramas por segundo |
| JavaScript comprimido | 260 KB |

## Lo que salió por el camino

- [Redondear un punto 16 m cambiaba su enlace de 100% a 93%](2026-11-14-06-dieciseis-metros.md).
- [Un retraso de cinco meses lleva la cresta de 100% a 28% de luz](2026-11-14-07-estaciones-lunares.md).
- Las cabeceras de seguridad no rompen la app compilada: se comprobó con las mismas pruebas de navegador.
